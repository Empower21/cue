1. What you actually have right now

There are two places the name "cue" shows up. They are different:

2. First look — the overlay

When the dev build is running, you see a narrow dark panel with rounded corners. Top to bottom:

  1. Header bar. Says cue on the left, and on the right has four controls: End (ends this session with confirmation), Context, a gear (⚙) for Settings, and a square (▢) to collapse the window to a pill.
  2. Mode selector. Three pills: Listen, Ask, Auto.
  3. Start/Stop bar. A blue Start button (becomes Stop once running), plus two voice-activity dots: you (mic) and them (system audio). The dots flash green when that channel is hearing voiced speech.
  4. Main area. Empty until you press Start. Then shows the live transcript, plus — depending on mode — an Ask input or a stack of streaming Answer cards.
  5. Footer. Shows the current mode and any error string.

3. Pasting context (JD, resume, role/company)

  1. Click Context in the header.
  2. Paste:
    • Job description — the full posting text.
    • Resume — your resume in plain text. (No file upload yet; just copy/paste.)
    • Role / company — short note like Staff PM, Acme Corp, Series C.
  3. Click Save.

Behind the scenes those three strings are written to %APPDATA%\cue\config.toml on Windows (or ~/Library/Application Support/cue/config.toml on macOS), and are pinned in the Anthropic prompt cache so every answer you generate is grounded in them without paying full cost each turn.

Your data does not sync across machines. The config file is local. If you reinstall or move to a new computer, you'll re-paste.

4. The three modes

Listen

Transcribes both sides of the conversation in real time. No AI answers — just notes. Best for capturing meeting minutes or study sessions where you want a transcript later but don't want the LLM in the loop.

Ask

Manual mode. While the transcript runs, type a question in the box at the bottom and press Ctrl+Enter (or click Ask). cue sends the question plus your JD + resume + role + the last ~10 turns of transcript to Claude, and streams back an answer in the card above. Each new Ask resets the answer card — so there's no clutter, but also no history.

Auto

Listens to the "them" channel (system audio = the other person on the call) and tries to detect questions. Triggers when:

  • The line ends with a ?, OR
  • The line starts with one of: what / how / why / when / where / who / can / could / would / should / is / are / do / does / did / tell / describe / explain

There's a 3-second debounce so back-to-back questions don't fire twice. Each detected question produces a streaming answer card; old cards stay on screen indefinitely — newest at the top. (There is no clear-list button yet — see section 6.)

5. Moving, collapsing, and hiding the window

Move it

Click-and-drag the header bar (the strip with cue on the left and the buttons on the right). Avoid clicking on a button or input — those are excluded from drag.

The drag is JS-driven, not native. On Windows it's been intentionally implemented this way because the OS caption-drag was breaking against Aero Snap. The trade-off is that drag can feel a half-frame behind on a busy CPU.

Collapse to a pill

Click the ▢ button in the header. The window shrinks to a 140 × 32 rounded pill that still hides from screen-share. Click ▢ again on the pill to expand back to 360 × 480.

Get it off the screen

You have three options today:

  • Collapse to the small pill — keeps the session running but takes almost no space.
  • Drag it off-screen — because it's always-on-top, it'll come back when you drag it on again.
  • Close the window — clicking X is intercepted in v0.1 (the close hides instead of quits). To fully quit you stop the dev process (Ctrl+C in the terminal running pnpm dev).

Toggle visibility from anywhere with the hotkey

Press Ctrl+\ on Windows (Cmd+\ on macOS) from any application — the cue overlay hides if visible, shows if hidden. The hotkey is registered globally (the OS forwards it to cue even when another app has focus), so you can stash and recall the overlay mid-call without alt-tabbing.

If the hotkey doesn't fire: another app on your machine may have claimed Ctrl+\. The Rust log line you want is global shortcut registered: CmdOrCtrl+Backslash in the dev terminal. If you don't see that line, the registration failed (usually because someone else has it bound). Fix: close whichever app holds the chord, or change the binding in apps/desktop/src-tauri/src/overlay/hotkeys.rs (the TOGGLE_SHORTCUT constant).

6. Ending a session — clearing answers, transcript, and optionally context

Click End in the header. A confirmation panel appears:

End this session?

 • Stops transcription
 • Clears all answer cards
 • Clears live transcript

 [ ] Also clear pasted Job Description, Resume,
     and Role/Company
     API keys are kept either way.

                       [Cancel]  [End Session]

Two ways to use it:

  1. Quick reset (checkbox unchecked). Stops capture, wipes the answer stack and live transcript, but keeps your pasted JD / Resume / Role-Company. Use this between back-to-back interviews against the same prep.
  2. Full wipe (checkbox checked). Same as above, plus blanks the JD / Resume / Role-Company fields in config.toml. Use this when you're done with a job-hunt cycle or handing the laptop to someone else.
What it does not touch: your Deepgram and Anthropic API keys, your window position, or your mode selection. Keys live in the same config.toml but the End Session flow deliberately leaves them alone — clear them manually via the gear (⚙) if you need to.

Other reset paths (still available)

You want to clear…How
Just the current Ask answer Type a new question — the card resets on each Ask.
Just the rolling transcript window the LLM sees (last 10 turns) Press Stop then Start. The Rust-side buffer is rebuilt on each Start.
Your Deepgram / Anthropic key Open the gear (⚙), select the field, delete, Save.
Absolutely everything including keys Close cue and delete %APPDATA%\cue\config.toml (or ~/Library/Application Support/cue/config.toml on macOS).

7. Using cue during a real call

There is no per-platform setup. cue works the same way in any conferencing or recording app on Windows or macOS, because the two mechanisms it depends on are OS-level:

  • Screen-share invisibility. The overlay sets WDA_EXCLUDEFROMCAPTURE on Windows and NSWindow.sharingType = .none on macOS. Any app that uses the OS's standard screen-capture APIs (Zoom, Google Meet, Microsoft Teams, Webex, Slack Huddle, Discord screen-share, Loom, OBS using Display Capture) will see the screen behind the overlay, not the overlay itself.
  • System audio capture. cue records the system audio loopback on its own (WASAPI loopback on Windows), so it hears the other person regardless of which app they're talking to you through.

Pre-call checklist

  1. Start cue. Paste JD + resume + role/company under Context. Save.
  2. Pick a mode: Auto if you want hands-free answers, Ask if you want to control when the AI speaks, Listen if you just want notes.
  3. Press Start. Confirm both voice dots flash green: you when you speak, them when the other party speaks. (If them never flashes, see Troubleshooting.)
  4. Position the cue window outside the area your camera shows and outside any window you'll be sharing. (It hides from screen share, not from your webcam.)
  5. Join the call as normal. No "activation" needed inside Zoom / Meet / Webex.

Verifying invisibility — do this once before a real interview

  1. Open Zoom (or any of the others) and start a meeting with yourself.
  2. Share your screen.
  3. Check the share preview thumbnail. The cue overlay should be absent from the preview while still visible on your monitor.

If you see cue in the share preview, see Troubleshooting → screen-share leak.

Two cameras worth of risk: (1) the overlay is hidden from screen share but not from your webcam — if your camera physically points at your monitor, it'll see cue. (2) remote-proctoring software (Proctorio, Examity, HonorLock) bypasses the OS screen-capture API and takes raw framebuffers — cue is not hidden from that, by design. See LICENSE.

8. Installing on another machine

The site at cue-web-five.vercel.app/download detects your OS and offers a .msi (Windows) or .dmg (macOS). Right now both return HTTP 404 because no GitHub Release has been tagged yet.

So today you have three real paths to a second machine:

Path A — wait for v0.1.0 (easiest, but blocked on you)

  1. Push a v0.1.0 tag to the GitHub repo with the built MSI attached.
  2. The download page will start serving it automatically (see apps/web/lib/github-release.ts).
  3. On the second machine: open cue-web-five.vercel.app/download → click the platform-detected button → install.

Path B — copy the locally-built MSI

Per CHANGELOG.md a release MSI was built on 2026-05-10. It's at:

cue\apps\desktop\src-tauri\target\release\bundle\msi\cue_0.1.0_x64_en-US.msi

Copy that file to the second machine (USB / OneDrive / Dropbox), double-click it. The MSI carries the placeholder build-time keys baked in, so you'll still need to open Settings on the new machine and paste your Deepgram key.

Path C — clone the repo and run dev mode on the second machine

Same flow you're using now. The other machine needs:

  • Node.js 24 LTS, pnpm 9+
  • Rust 1.78+ (rustup.rs)
  • On Windows: Microsoft C++ Build Tools (Visual Studio Installer → "Desktop development with C++")
  • On macOS: Xcode Command Line Tools (xcode-select --install)
git clone <your-cue-repo-url>
cd cue
pnpm install
pnpm dev

This launches the same dev overlay you're using now.

9. Settings & API keys

Click the gear (⚙) in the header. Two fields:

  • Deepgram API key. Required to press Start. Get one free at deepgram.com — they hand out ~US$200 of credit which is enough for hundreds of hours of streaming STT.
  • Override Anthropic key (optional). The MSI ships with an Anthropic key baked in at build time via CUE_ANTHROPIC_KEY. If you want to use your own personal Anthropic key (and your own usage caps), paste it here.

Both are stored as plaintext in config.toml — see section 3 for the path. Treat that file like any other API-key file on your machine.

10. Troubleshooting

"capture already running" / Start button does nothing

Most likely the audio session is stuck from a previous run. Click Stop, then Start again. If still stuck, close the cue window (or Ctrl+C in the dev terminal) and restart.

The them dot never lights up

You're capturing your mic but not system audio. Checks:

  • Audio is actually playing out of your speakers / headphones (cue captures loopback on the default output device).
  • You haven't routed the call audio to a virtual cable / Bluetooth device that's not the default output.
  • On Windows, verify in Sound settings → Output that the active device is the one playing the call audio.

Answers say "Anthropic unavailable — falling back to HuggingFace Mistral-7B"

This is the orchestrator doing its job. It means either no token arrived from Claude within 8 seconds, or Claude returned an error before any token. Causes:

  • Anthropic credit balance hit zero.
  • API key invalid or revoked.
  • Network blip.

Top-up at console.anthropic.com, or paste a valid override key in Settings.

Screen-share leak — cue is visible in the Zoom/Meet share preview

  • Confirm you are using a recent Zoom / Meet / Teams version. Very old builds bypass the OS exclusion list.
  • Confirm you are using screen / display / window share, not a virtual camera that re-captures the display.
  • On macOS, the OS sometimes resets sharingType after a system update — restart cue.

"Deepgram API key not set in Settings"

Open the gear, paste a key, Save, then try Start again.

Ctrl+\ hotkey stops working after cue has been up for a long time

Known long-uptime issue on the alpha. The Windows RegisterHotKey binding can drop after many hours and several Vite hot-reloads of the dev build. Fix: fully quit and relaunch cue. Confirm via the log line global shortcut registered: CmdOrCtrl+Backslash on the fresh launch — that proves the OS accepted the registration. Tracking for v0.1.x.

Window won't drag

Make sure you're click-dragging the header strip, not a button. The header has a 6-pixel grab handle indicator at the top center.
